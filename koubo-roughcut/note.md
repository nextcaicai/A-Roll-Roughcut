# 口播粗剪：关键变动

现行步骤在 `SKILL.md`。这份 note 只记**改了什么、为什么改**。命令、字段、阈值以 skill 和 `references/` 为准，这里不复写。

当前版本：`0.12.7`（2026-09-28）。

## 怎么续写

取舍规则、流水线顺序、交付物、审片交互原则变了，当次就在下面**追加一条**，新的放最上面。一条写清四件事：当时怎样、改成怎样、为什么、明确不走的路。

面板配色、单次 run 的修 bug、没有改变下次怎么剪的实现细节，不单列。

## 现在的形态

口播粗剪的真源是 `cut_decisions.json`。人在浏览器面板里把划线定稿，打开就是剪后播放。右上角可以导出按剪后时间对齐的字幕 SRT，以及定稿后的固定帧率成片。FCPXML 用命令行导出。点导出打开系统存储框，可以改名，下次默认打开上次的文件夹。转写默认用百炼录音文件识别 `paraformer-v2`。不用 realtime，不用本地 Whisper。用户明确指定时，可以改用豆包录音文件识别 2.0。

流水线顺序固定：先修字 → 再少误删、收气口、清词级卡顿 → 通读复查 → 人在面板定稿。收气口到残留扫描是一条命令 `pipeline.py`。不跑 Jev。审片记录以第一次开面板时的 JSON 为基准，跨多次打开累计。人说「学一下」时先汇总差异，确认后再写入规则。

从 2026-09-21 第一版到现在，没改过的原则：

- 不确定就进 `flags`，不删。不改音频。口播用词不贴脚本。ASR 听错的字在删词前修。
- B-roll 不自动盖。不写剪映草稿 JSON。ChatCut 不做粗剪主场。
- `runs/` 可删，必须能从源片 + 脚本 + skill 重建。

## 变动

### 2026-09-28 · 审片不再提供隐藏已删字

**当时：** 顶栏有「已删可见」。再点一次会把划掉的字和气口从逐字稿里藏掉。

**改成：** 按钮拿掉。划掉的字一直留在逐字稿里，可以点、可以框选恢复。

**为什么：** 审片要看见删了什么，并把误删找回来。藏起来之后这些字点不中，也框不回来。听成片已经由剪后播放负责。

**不走：** 把已删的字从逐字稿里拿掉。

### 2026-09-28 · 审片打开就是剪后，XML 改走命令行

**当时：** 面板默认播源片，要再点「剪后」才跳过删掉的句子。右上角同时放着「源片 / 剪后」和「导出 XML」。逐字稿和画面的分界是固定比例。通听只能用播放器自己的倍速。

**改成：** 打开就是剪后。面板上不再放源片/剪后切换，也不再放导出 XML。倍速可选 1.0、1.1、1.2、1.3。逐字稿和画面中间的线可以左右拖，宽度会记住。FCPXML 仍用命令行导出。

**为什么：** 审片要听的是剪完的成片。源片对照和每次都导出 XML 占着顶栏，但不是这一轮的主操作。1.1 到 1.3 能加快通听，又留得住口误。分界固定时，长逐字稿和画面抢同一块宽度。

**不走：** 把已删的字从逐字稿里拿掉（划掉的字还要能看见、能改）。从脚本里删掉 FCPXML 导出。

### 2026-09-27 · 整段删掉之后，中间气口不再留着

**当时：** 气口压缝会在下一词前留下 0.4 秒吸气。词级卡顿或整段重说把后面的字删了，这口气还在 keep 里。成片中间冒出几段空白，审片里 `[...0.4s]` 也没划掉。

**改成：** 没有字、又不挨着留下的那句的 keep，改成 `long-pause`。还贴在留下的字边上的吸气保留。

**为什么：** 人已经决定整段不要，中间换气没有成片价值，留着只会让删段听起来一顿一顿。

**不走：** 把所有 0.4 秒气口都删掉（句间换气还要）。为这一步重跑转写。

### 2026-09-27 · 隔口气重起的开头要删，keep 头尾静音也要压

**当时：** 词级卡顿只认 0.45 秒内的叠字。「情况。所以」停 1.3 秒再「所以经常…」不算叠字，成片里两个所以都在。气口只剪 keep 内部词缝，一段 keep 划到下一刀之前时，删完重说后尾巴还能留下 3 秒静音。

**改成：** 句号后的短开头，隔了一口气又重说，删前面那截。一段 keep 第一个词之前、最后一个词之后多出来的停顿，写成 `long-pause`。下一句的 lead-in 仍回退 0.12 秒。

**为什么：** 这两种都是人一眼能看出来的废镜头，脚本不剪，审片就得手删。

**不走：** 把叠字间隔放到 2 秒（会误伤句间重复的词）。keep 尾部再留 0.4 秒气口（下一句入点已经有吸气余量）。

### 2026-09-27 · 整段重说默认留后遍，建议听只负责复核

**当时：** 「有限解」整节录了两遍。后遍多了「提前拆解」，结尾却说成「更简单」。模型把「不是谁完全盖住谁」理解成两遍都留，把判断整段甩给人。

**改成：** 同一内容又录一遍，默认删前留后，`flags` 仍写上让人听。后遍个别句子更残，不因此改留前遍。只有后遍整段明显更残、信息更少，才留前遍。

**为什么：** 审片是复核，不是替模型做第一刀。整段重说已经听得出来，两遍都留会让成片先长一截，人也要先听完重复才知道该删哪遍。

**不走：** 后遍有一句不好就整节都留。拿掉建议听（人还是要能改回前遍）。

### 2026-09-27 · 审片差异能变成候选规则，残留表少报已删对的卡顿

**当时：** 「学一下」要 agent 自己翻 `review_log.json`，旧日志还经常是空的，容易编规则。残留扫描把改口失败开头、以及隔了很远才出现的重说，都报成夹缝误删。表一长，第 6 步就不看了。

**改成：** 第 8 步先跑 `learn_preferences.py`，按恢复 / 新删 / 没听分组写出 `preference_candidates.md`。模型只把重复出现的或会改成片结构的列为候选，确认后再写入 `semantic-deletion.md` 或专名表。残留扫描只把前后都挨着的 stutter 当夹缝；改口、叠字后说、后一句已经接上的，不再报。

**为什么：** 学偏好的原料已经在审片日志里，缺的是汇总和「先确认再写」这条闸。残留表噪音大，真正误删会被一起忽略。

**不走：** 脚本直接改 `references/`。把一次空日志当成「人全盘采纳」。继续用远处的下一句 keep 判断夹缝。

### 2026-09-27 · 每次 run 留下可比较的数字，keep 的字对上这段

**当时：** 调气口或取舍之后，只能凭感觉判断剪得更好还是更坏。JSON 里几段 keep 常抄同一句整句，agent 读 `text` 会以为这段还含已经划掉的字。残留扫描看夹缝时也读这句整句。

**改成：** 第 5 步结束写 `run_summary.json`：源片/成片时长、压缩率、各类 drop 条数、覆盖缺失、残留条数。审片保存后补上人恢复/新删了几处。keep / drop 的 `text` 改成这段时间里真正落进来的词。

**为什么：** 没有尺子就无法判断下次改规则是进步还是退步。字对不上时间，对照和残留都会看错。

**不走：** 每次跑完用对话里的散文汇报代替落盘。让模型手改 `text` 字段。

### 2026-09-27 · 默认路径拿掉 Jev

**当时：** 第 5 步枚举成对重说后，用 TypeSafe 的 Jev 判定并合并进 JSON。开工要 `TYPESAFE_API_KEY`。

**改成：** `pipeline.py` 只跑气口、词级卡顿、脚本覆盖、残留扫描。SKILL 和 `setup_check.py` 不再要这把 key。判定脚本还在 `scripts/` 里，不进默认流程。

**为什么：** 六次实跑里，修字后的成片 Jev 新删 0 秒；它认为该删的大半第 4 步已经划掉。有增量的一次误删了成片里唯一的再见。多一把 key、多一轮调用、审片多几条不一定是重说的 flag，换不来成片质量。

**不走：** 缺 key 就跳过但仍写在默认步骤里（agent 还是会去要 key）。把判定脚本删掉（以后若要复验，手跑即可）。

### 2026-09-27 · 气口压缝真的剪掉多出来的停顿

**当时：** `compress_breath.py` 把长停顿拆成「speech + breath」两段 keep，首尾相接，成片时长不变。`codex多模型` 最近一次定稿里还剩 40 处长于 0.4 秒的停顿，多出大约 20 秒。skill 写的是压到 `maxKeep`，脚本从第一天就没这么做。残留扫描把已经删对的卡顿（后一句已经包含前半截）也报成疑似误删。

**改成：** 先把首尾相接的 keep 合成一段（旧脚本留下的 speech+breath 就是这样），再压词与词之间长于 `maxKeep` 的空隙：只留下一词开始前的 `maxKeep` 当气口，多出来的写成 `long-pause`。字尾不伸进停顿；切口贴在下一词前，避开吸气峰。一段 keep 头尾原来的静音不动。`codex多模型` 那次定稿重跑能收掉约 20 秒。残留扫描：drop 的字被紧挨着的下一句 keep 包含，或两段共享 8 字以上开头，不再报。

**为什么：** 气口规则写了三年，成片停顿却一直靠模型和面板手删。脚本不剪，agent 也不会发现漏了。误报一多，残留表就没人看。

**不走：** 改 skill 去迁就脚本。按字尾去切（会切在吸气上）。用 ffmpeg 静音检测替换词时间（词时间已经够用，静音检测是另一条未接入流水线的旧脚本）。

### 2026-09-27 · 审片记录留得住人的判断

**当时：** `review_log.json` 的基准是「这次打开面板时的 JSON」。`Jev模型` 那次开过两次面板：第一次删了几段几十秒的内容，第二次打开时基准被换成已改过的 JSON，日志写着 0 处改动，流水线原本删了什么、人推翻了什么都查不到了。面板里手删的字 reason 记成 `uncertain`，和流水线拿不准的混在一起。diff 按 `(起点, 终点, 文字)` 严格匹配，恢复半段 drop 会记成「恢复一条 + 新删一条」。`flags` 没有听没听的状态：160 秒那条还写着「两遍都先留」，实际前遍已删、留下的是 `review.md` 自己说结尾坏了的后遍，分不清是听过定的还是漏了。

**改成：** 第一次开面板时把 JSON 存成 `cut_decisions.pipeline.json`，之后都跟它比；重跑第 5 步才换。diff 按时间比剪掉了什么，拆条、改 reason 不算变化。手删的字记 `manual`。建议听点一下就记为听过，顶部显示还剩几处，导出时提醒；`review_log.json` 列出没点开的。

**为什么：** 学偏好只能从「人实际推翻了流水线什么」学。基准一换，原料就没了。建议听是流水线把判断交给人，交没交到要有记录。

**不走：** 让人手动备份日志。导出前弹框拦着「还有没听的」（导出不是风险操作，提醒就够）。把听过做成要额外点的勾选框。

### 2026-09-27 · 收缝到残留扫描合成一条命令，校验收紧

**当时：** 第 4 步到第 7 步要 agent 手动串十几条命令，编号是 4、4a、5、6、6b、7，脚本报告里还写着 Step 2.5。`validate_decisions.py` 不查 drop 和 keep 重叠。`apply_proposed_drop` 找 keep 时容差 0.025 秒，却不把 drop 夹回 keep 边界，会咬进下一段 keep；卡顿跨在两段首尾相接的 keep 上时直接跳过（`如何学习AI？` 一次跳过 14 条）。Jev 的 `TYPESAFE_API_KEY` 在 SKILL、`AGENTS.md`、`setup_check.py` 里都没写。

**改成：** `pipeline.py` 一次跑完气口、入点、词级卡顿、重说候选、Jev、合并、覆盖、残留，开跑前先查修字稿、JSON 校验和 Jev key，哪步失败就停并给出 `--from`。步骤重排为 1–8 整数。校验集中到 `decisions_common.decisions_problems`：同一段时间既留又删是错误，drop 互相重叠只提示。drop 夹回 keep 边界，可以跨首尾相接的 keep。字幕规则挪到 `references/subtitles.md`。

**为什么：** 机械步骤由人或 agent 手串，漏一步不会报错。新校验第一次跑就在重跑 Jev 那次的数据上拦下一处「既留又删」，旧校验会放过去。字幕规则由脚本执行，agent 不需要每次读。

**不走：** 缺 Jev key 时自动跳过 Jev（缺 key 就停）。把 9 月 23 日之前老 run 里的重叠数据自动修掉（runs 可重建，打开保存时会报错提示）。

### 2026-09-25 · 定稿后可导出固定帧率成片

**当时：** 面板只能导出 XML 和 SRT。源片帧率不均匀时，剪映按自己的格子排画面，字幕仍按秒贴，字和声音会错开。旧的拼接脚本没有收成固定帧率，也不在面板上。

**改成：** 右上角增加「导出成片」。按当前切口渲一条 mp4，帧率和 XML 相同。字幕仍单独导出。切口焊进这个文件，改一句要重新导。

**为什么：** 只改 XML 上的帧率标记，消不掉源片里长短不一的画面。定稿后要进剪映对字幕，需要一条一格一格一样长的成片。

**不走：** 用这条 mp4 代替 JSON 当粗剪真源。为了对齐字幕把成片重新转写。

### 2026-09-24 · 导出用整数帧率，字幕不跨切口

**当时：** FCPXML 用源片报出来的峰值帧率。这支片子是 `299/12`。字幕按真实秒数另算，而且一张字幕可以跨过切口，从残留的字开始就把后面的句子显示出来。

**改成：** 时间轴收成最近的整数帧率（24/25/30/50/60）。这支片子收成 25 帧。字幕入点和 XML 切口落在同一格。两段之间删掉的原片长于气口时，字幕从这里断开。挨得很近的切口仍合成一张，避免把「自」单独切出去。

**为什么：** 剪映的时间轴认整数帧率，`299/12` 要它自己换算，画面和字幕会错开。跨切口时，整句会在前一个残留字上就出现。

**不走：** 把源片转成固定帧率再转写。把所有字幕统一往后推。渲一条拼接 mp4 来重做字幕。

### 2026-09-24 · 导出用系统存储对话框，可以改名

**当时：** 先选文件夹，同名时再弹一个只有「取消」和「覆盖」的框。文件名不能改。那个框是系统窗口，但按钮和文案是自己写的。

**改成：** 点导出打开系统的存储对话框。名字预先填好，可以直接改。如果还是同名，由系统询问是否替换。下次默认打开上次保存的文件夹。

**为什么：** 重名时人要的是换个名字留下两份，不是只能盖掉或放弃。系统存储框本来就会改名，也会在替换前询问。

**不走：** 自己画一个只有取消和覆盖的对话框。自动在文件名后面加序号。

### 2026-09-24 · 字幕末尾不显示句读

**当时：** 每张字幕末尾带着口播转写里的逗号、句号。单独看一张时，这些符号像稿纸上的断句，不像字幕。

**改成：** 一张字幕末尾的逗号、顿号、分号、冒号、句号不写进 SRT。问号和感叹号留下。卡片中间的字不动。

**为什么：** 字幕是一张一张出现的，卡片边界已经是停顿。问号和感叹号会改变这一张的语气，不能一起拿掉。

**不走：** 把转写里的标点改掉。去掉卡片中间的逗号。把问号、感叹号也抹掉。

### 2026-09-24 · 字幕按完整短句断行，不改字

**当时：** 字幕按 18 个字硬切。一句没说完也会被切成两张，例如「如果用几 / 个标签」「适合大规 / 模自动化」。

**改成：** 一张字幕一行，短句和稍长的整句可以同时有。口播里已经有的逗号、句号，以及逐字稿里整句对得上的分句，不满一行也换下一张。一句已经收住、不超过 24 字，就整句留在一张里。再长才按大约 18 字在词界拆开。逐字稿只对上开头时，不断在半句上。拼回去的字必须和剪后留下的字一致。

**为什么：** 字幕要跟着口气走，不是跟着字数走。逐字稿和口播用词不一样，只能用来找断点，不能拿来改字幕。

**不走：** 一张字幕排两行。让模型润色字幕。用逐字稿替换口播用词。为了凑满 18 个字才允许断句。

### 2026-09-24 · 同名导出先问要不要覆盖

**当时：** 所选文件夹里已有同名的 XML 或字幕时，直接覆盖，没有提示。

**改成：** 选完文件夹后，如果同名文件已在，弹出「要覆盖吗」。取消则不写，原文件留着。文件夹里没有这个文件时，不额外询问。

**为什么：** 文件名按成片和这次 run 固定。再导一次会打到同一个文件上，人需要知道这次会换掉上一份。

**不走：** 静默覆盖。自动改名再存一份，让文件夹里堆着看不出哪份是最新的。

### 2026-09-24 · 导出时选择文件夹，并记住上次的位置

**当时：** 面板导出直接写进当次 run 目录，文件名固定是 `roughcut.fcpxml` / `roughcut.srt`。人要换地方，只能自己把文件搬走。

**改成：** 点导出先弹出文件夹选择。第一次默认打开本次 run 目录，之后默认打开上次选的文件夹。路径记在仓库根目录 `.export-dir`，不进 git。取消不写文件。写到所选文件夹的文件名是 `<成片名>-<run>.fcpxml` / `.srt`，避免两条成片导到同一文件夹时互相覆盖。命令行仍按 `--output` 写。

**为什么：** 导出是拿走成片，目的地应该是人指定的文件夹，而不是 run 目录。run 目录是这次粗剪的工作文件，下次重建可以丢掉。

### 2026-09-24 · 审片可分别导出 XML 和字幕

### 2026-09-23 · 词时间改用 paraformer-v2

**当时：** 本地 wav 没有公网地址时，转写走的是 `paraformer-realtime-v2`。它交回的词时间是一段里均分：大约 92% 的词落在「连续四个以上、时长相同」的格子里。切口贴着这些格子，波形上明明有缝也对不上。`codex多模型` 里「自行车」「你中途」「方法」都是这样。把切口挪几十毫秒，听感没有改过来。

**改成：** 同一条音频改用录音文件识别 `paraformer-v2`。时间戳校准开关仍开着。词长不再均分，字落到声音的每一截上。这次粗剪的词时间用的是这份转写。

**为什么：** 均分不是我们写的规则。实时接口返回的 `begin_time` / `end_time` 就是这样，格子边不是吸气或字与字之间的缝。文件模型和实时模型不是同一套词时间。粗剪要按字切，词界得落在声音上，不能落在均分格子上。

**不走：** 继续用实时模型的均分时间轴来切，再靠挪切口补。也不要把这次换成「所有识别模型都该换」——没拿同一段音频比过的，不这么说。

### 2026-09-23 · 按字切开的叠词不当卡顿

**当时：** 词级卡顿看到相邻两个相同的字，就删前一个。叠词白名单认的是「看看」这一个词。文件转写把字切开之后，「看」和「看」对不上白名单，`看看`、`拜拜`、`密密麻麻` 会被删掉一半。

**改成：** 相邻两个相同的单字，拼起来在叠词表里，就不删。表里补上 `某某`、`密密`、`麻麻`。

**为什么：** 叠词是说完整的一个词，不是口吃。按字对齐之后，白名单要认字，不能只认没切开的词。

**不走：** 为了消掉真卡顿，把叠词也删短。

### 2026-09-23 · 审片读修过的字

**为什么：** 修字只改判断用的文字。人在面板里改删留，看的应该是同一套字。

**不走：** 把修过的字写回 `transcript.json`。

### 2026-09-23 · 剪后提前跳只吃空白

**当时：** 剪后播放固定在 keep 结束前 40 毫秒跳到下一段，用来盖住播放器来不及跳。切口如果贴在还在响的字上，这 40 毫秒会把最后一个音切掉。

**改成：** 剪后把保留段播到切口再跳。跳转完成之前静音，避免删掉的句子漏出来。没有量到空白时，不再提前 40 毫秒跳走。

**为什么：** 提前跳会把上一个字的尾音跳掉。只把切口挪进空白、跳转本身仍提前，听感不变。跳转若来不及，删掉的下一句又会先响出来。

**不走：** 靠提前跳来挡住播放器延迟。两句之间没有缝时，提前跳解决不了漏字。

### 2026-09-23 · 先修字，再删词

**当时：** 转写原文直接拿去对照、取舍、词级卡顿和重说判断。听错的专名和真说错的话混在一串里，`group` 会被当成另一个词或一次卡顿。

**改成：** 转写之后、写 `cut_decisions.json` 之前先出修字表。脚本只替换对得上的词，时间与词数不动，原文留在 `transcript.json`。后面的删词步骤读 `transcript.corrected.json`。判据在 `references/semantic-deletion.md`。

**为什么：** 听错的字不是多余的话，删词修不掉它。字不对，后面的重说和卡顿判断会错，尤其是专名。

**不走：** 把口播自己的用词改成脚本措辞。拿不准就编一个写法。为了修字去改音频或重跑转写。

### 2026-09-23 · 气口可以单独划掉

**当时：** 字幕里的气口标记和字的时间叠在一起。划掉标记时，字的中点落进被切掉的区间，字也跟着出现删除线。框选也只认字，停顿只能连字一起删。

**改成：** 气口、静音和字用同一套鼠标框选。松手时，选区里还有留下的就划掉，全是已划掉的就恢复。划掉的气口留在原地，带删除线，可以再框一次恢复。只框到气口时，不带动旁边的字。

**为什么：** 人要收的是停顿，不是把停顿前后的字一起拿掉。标记划掉后如果从字幕里消失，就没法再框选把它恢复。

### 2026-09-23 · 审片里的静音必须能看见、能听成剪后的样子

**当时：** 气口压缝后，字幕里常常只剩文字挨着文字。面板用「气口 3.1s→0.4s」这种摘要。开「剪后」仍能听到已经划掉的句子。放大后的音轨不能左右拖。已删气口用亮黄，留下的气口用浅黄。

**改成：** 被划掉的静音或气口以「划掉了多少秒」出现在字幕里，颜色和已删文字一致；留下的气口用灰。剪后播放只走 keep。放大后的波形可以左右拖。

**为什么：** 人要决定留不留、恢不恢复，得看见那几秒被划掉了，而不是看见一条压缩公式。字和字之间如果没有气口标记，会以为那里本来就没有停顿。听的必须是剪完的片子，否则定稿时判断的是另一条时间线。
