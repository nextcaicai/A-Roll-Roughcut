# 语义删除规则

判断教材。步骤顺序在 `SKILL.md` 第 2 步：修字表落成 `transcript.corrected.json` 之后，才做删词。`transcript.json` 仍是听写原文。

## 修字和删词是两件事

| | 修字 | 删词 |
|---|---|---|
| 发生了什么 | 人说对了，机器听错了 | 人先说错或不完整，又重说了一遍 |
| 音频 | 不动 | 删掉前面那一遍 |
| 例子 | `group` 其实是 Grok | 「因为这个任务。」改口成「因为这个定时任务……」 |

听错的字不是多余的话。删词修不掉它；不先改字，专名就会被当成另一个词、一段废话，或一次卡顿。

`validate_script_coverage.py` 挡不住这个。它在删完之后才看 keep 里有没有稿上的正确写法。keep 里若仍是 `group`，正确的「Grok」对不上，有脚本会假报缺失，没脚本（如 `grok使用`）这步直接跳过。

## 顺序

```text
转写 → 修字表 → 再按修过的字做删词 → 气口仍是机械步骤，不算语义删除
```

修字只服务判断。不改 `transcript.json` 的时间，不改音频，不把脚本里有、嘴里没说的句子补进成片。

字的来源，高的优先：

1. 听得清的口播说法
2. `脚本.md` 里的专名写法，只用于对齐听错的字
3. `references/proper-nouns.txt`
4. 对不上就不猜，原字留下，写进 `review.md`

口播用词和脚本不同，按口播留。`codex多模型`：嘴里说的是航母 / 自行车，脚本是核武器 / 坦克，不贴脚本。

## 删词原则

```text
前一次不完整或说错  →  删除
后一次完整或说对    →  保留
```

默认删前保后，`flags` 仍写上让人听。后遍个别句子更残，不因此改留前遍。只有后遍整段明显更残、更糊、信息更少，才留前一遍。

两遍各有对方没有的信息，都留。那是补充，不是重说。

不确定就不删，进 `flags`，审片时听。成风把高风险复核完就直接删、不设第三态；我们有审片面板，`flags` 继续留着。

判断「相邻」时看的是修字之后、将要播出来的顺序。源片上隔很远的两句，剪完可能挨在一起。

气口、lead-in 不属于这里。单个自然语气词不删。

## 五类

每类只认自己的样子。已经归到修字的，不要再当删词。

| 类 | 认什么 | 不认什么 |
|---|---|---|
| 整段重说 | 同一意思又录了一遍 | 后遍整段更残；两遍各有独有信息（那是补充，不是重说） |
| 句内残句 | 半句、改口，只删前面失败片段 | 顺手删掉后面完整句 |
| 口误重说 | 嘴里先说错专名或数字，后面说对了 | 机器听错、人没说错（那是修字） |
| 词级卡顿 | 相邻同一字、同一词的口吃，且不是叠词 | 专名被听成碎片段；产品名里本来就有的重复字 |
| 气口 | 不在本规则里 | — |

## 判例

四行：原文（口播顺序）→ 删 → 剩下读作 → 为什么。只收已经在 run 里定过的。扫描疑似、人还没听的，放在文末，不升成判例。

**R1 · 整段重说留后遍**（`grok使用` / `20260923-0830`，用法二）

```text
原文：【309s 第一遍，Imagine 和传播节点上断了两次，末尾还有一句再见】410s 后遍把 loop engineering、传播节点、subagent 说完
删：第一遍整段（含那句提前的再见）
剩下读作：用法二的完整后遍
为什么：后遍覆盖前遍，且多出前遍没有说完的内容
```

**R2 · 句内只删失败开头**（同一次 run）

```text
原文：【因为这个任务。】因为这个定时任务并不涉及复杂推理
删：前面半句
剩下读作：因为这个定时任务并不涉及复杂推理
为什么：改口。只删残句，不删后面完整句
```

**R3 · 后遍更残，留前遍**（同一次 run，API 句；`codex多模型` 的演示和 GUI 同类）

```text
原文：约 8:04 的完整句 【8:20 起「P如 group p to api」碎掉的后遍】
删：后遍
剩下读作：前一遍
为什么：后遍不是更完整，是更残。必须写 flags。不要用「较短」代替这个判断
```

**R4 · 后遍没再讲的那句要留**（`grok使用`，用法一标题）

```text
原文：定时任务驱动 grok cli，四个工具 【后面只重录了四个工具和例子，没再讲这句标题】
删：（不删标题句）
剩下读作：标题句 + 后遍的工具说明
为什么：两遍不是同一句。删前保后不能把只出现过一次的信息带走
```

**R5 · 听错的专名先修字，不当重说**（`grok使用` 弱匹配，尚未改字）

```text
原文：hammers / body、group / groi / gra、looengineering、media
删：（不因这些字而删）
剩下读作：判断时按 Hermes、Workbuddy、Grok、loop engineering、推理强度来读
为什么：人没说错。字不对时，重说匹配和「这段是废话」都会误判。修字不改音频
```

**R6 · 产品名里的重复字不是卡顿**（同一次 run，已改回）

```text
原文：imagine image 2.0
删：（词级脚本删过前一个 image，已恢复）
剩下读作：imagine image 2.0
为什么：两个 image 不是口吃。前一个属于 imagine。专名和产品名先修字、先对照，再跑词级卡顿
```

**R7 · 口播和脚本用词不同，不贴脚本**（`codex多模型` / `20260922-1649`）

```text
原文：航母 / 自行车
删：（不删，也不改成脚本的核武器 / 坦克）
剩下读作：航母 / 自行车
为什么：修字只修听写，不修人的用词。脚本不能逐字 diff
```

**R8 · 收尾只剩一遍时不能当重复删**（`grok使用`，Jev 判完已改回）

```text
原文：成片里只剩一句再见；另一句是已经删过的重复
删：（不删这句再见）
剩下读作：保留这句收尾
为什么：候选文本像重复，播出来已经没有另一遍。删了就没有再见
```

## 还不能当判例

`如何学习AI？` 的残留扫描里，词级卡顿切过 `Claude`、`Code、Cod`、`Groove`。形态和 R6 一样：专名碎片被当成口吃。人还没在审片里逐条恢复，先记在这里，不定成规则。

## 高风险时多看一遍

整句、长段、同开头后半分叉、专名或数字改口、后遍是否更残：先按修过的字把前后念通。念不通就不列为删除，改 `flags`。

低风险才直接删：前一遍被后一遍完全包含；明确的单字口吃，且不在专名、叠词白名单里。

## 还没做的

- 不把修字写回 `transcript.json`
- 审片里人恢复或补删的：跑 `learn_preferences.py` 出候选，确认后再按四行格式追加。全盘采纳也记一笔，避免只记住出错的片
